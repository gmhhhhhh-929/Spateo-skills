# Detect Spatial Components

## Package paths

Run the relative commands below from this skill directory. Keep this subskill inside the complete `spateo-2d-alignment` directory.
The shared support tools are the fixed pre-zebrafish snapshot, located in
`../../pipelines/pairwise-rigid`. Verify entrypoints with its `skill.lock.yaml`.
This packaging restoration does not change alignment algorithms or defaults.


Use this skill after a slice-level baseline has been composed. It labels
connected tissue islands within each slice and prepares the labels used by
balanced300k sampling, HTML viewer Component mode, and later component-level
candidate alignment.

This skill only detects and visualizes components. It must not decide
cross-slice matches or apply coordinate corrections.

Manual review should first use the full-points HTML viewer generated by
`spatial-pointcloud-viewer`, because the decision that a component is truly
wrong should be made on full data. After a candidate edit, use balanced300k
viewers for fast structure checks and iteration. Both viewer types should color
by Component and show in-view labels such as `SL59 rank2 id7`. The PNGs
generated here are detector QC sidecars, not the primary review interface.

## Entrypoint

Use the locked detector from the active release:

```text
../../pipelines/pairwise-rigid/scripts/components/detect_components.py
```

Resolve it through `../../pipelines/pairwise-rigid/skill.lock.yaml` and record the entrypoint sha256 in the
step provenance.

## Standard Command

```bash
python ../../pipelines/pairwise-rigid/scripts/components/detect_components.py \
  --input exports/<sample>.slice_level_baseline.clean_coordinates.csv \
  --output-dir steps/<step_detect_components>/qc \
  --slice-col sl_number \
  --x-col x \
  --y-col y \
  --cell-id-col cell_id \
  --celltype-col celltype \
  --bin-size auto \
  --close-radius-bins 2 \
  --min-points 50 \
  --min-fraction 0 \
  --max-components 0
```

Use full-resolution baseline coordinates for final component labels. Sampling
is acceptable for temporary plotting, but not for the authoritative
`component_labels.csv`.

## Required Outputs

```text
qc/component_labels.csv
qc/component_summary.csv
qc/component_detection_manifest.json
qc/figures/slice_<slice>_components.png
```

The PNG is a required QC artifact. It should color each component and show a
legend with rank, component id, and point count, for example:

```text
SL59 rank1 id3: 15432
SL59 rank2 id7: 2841
SL59 noise: 126
```

Component ids are per-slice labels. Human-facing notes and candidate recipes
must identify a component as `<slice> rank<rank> id<component_id>`, for example
`SL59 rank2 id7`; do not write only `rank2` or `id7`.

After detection, ensure both the full-points review table and balanced sample
preserve component labels so the HTML viewer can display them in Component
mode.

## Checks

- Each slice expected in the baseline appears in `component_summary.csv`.
- `component_labels.csv` preserves the original clean `cell_id`; do not
  renumber cells.
- Small components remain visible if they may be used as anchors.
- Noise is clearly marked as `component_id=0` and shown in grey in PNGs.
- The number of components is stable enough under the selected bin size and
  closing radius for human review.
